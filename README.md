# 3D Printer Farm Monitoring System

This project implements an Edge–Fog–Cloud architecture for monitoring a cluster of simulated 3D printers. Telemetry generated by simulated printers is processed by a FastAPI-based fog node, transmitted asynchronously through Amazon SQS, processed by AWS Lambda, stored in Amazon DynamoDB, and visualized using a Streamlit dashboard hosted on Amazon EC2.

The system demonstrates scalable cloud-native monitoring, event-driven processing, and real-time visualization using AWS services.

---

## Features

- Real-time telemetry simulation for a fleet of 3D printers
- Monitoring of key printer metrics:
  - **Nozzle temperature**
  - **Bed temperature**
  - **Vibration level**
  - **Filament flow**
  - **Print progress**
  - **Printer status**
- FastAPI fog node for local ingestion and preprocessing
- Local anomaly detection at the edge/fog layer
- Amazon SQS message queue for asynchronous, decoupled communication
- AWS Lambda for serverless event-driven processing
- Amazon DynamoDB for scalable telemetry storage
- Streamlit monitoring dashboard for real-time visualization
- Amazon EC2 deployment for dashboard hosting

---

## System Architecture


The system follows a three-tier Edge–Fog–Cloud architecture:

1. **Edge Layer** – Simulated 3D printers generate telemetry data.
2. **Fog Layer** – A FastAPI node ingests, preprocesses, and forwards telemetry, performing local anomaly detection where applicable.
3. **Cloud Layer** – AWS services (SQS, Lambda, DynamoDB, EC2) handle asynchronous processing, storage, and visualization.

## AWS Architecture



The AWS layer consists of:

- **Amazon SQS** – buffers telemetry messages from the fog node
- **AWS Lambda** – consumes messages from SQS and processes/stores them
- **Amazon DynamoDB** – stores processed telemetry data
- **Amazon EC2** – hosts the Streamlit dashboard
- **Amazon CloudWatch** – provides logging and monitoring for Lambda and EC2


Install requirements for each module:

## Sample Workflow

```text
Simulator
   ↓
FastAPI Fog Node
   ↓
Amazon SQS
   ↓
AWS Lambda
   ↓
Amazon DynamoDB
   ↓
Streamlit Dashboard
```

1. The simulator generates telemetry (nozzle temperature, bed temperature, vibration level, filament flow, print progress, and printer status) for each simulated printer.
2. The FastAPI fog node receives this telemetry, performs local preprocessing/anomaly detection, and forwards it to Amazon SQS.
3. AWS Lambda is triggered by new messages in the SQS queue, processes the data, and writes it to Amazon DynamoDB.
4. The Streamlit dashboard, hosted on Amazon EC2, queries DynamoDB and displays real-time printer status and metrics.
